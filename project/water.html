[ Case study (01) ] — Product design · Poker companion app · In development

Water

A redesign of a poker companion app people use one-handed, at the table, in low light. I proposed a new layout language, explored the homepage over six rounds, built the clickable prototype and wrote the specs engineering builds from — plus a Design Hub that keeps design, PM and dev on the same page.

Role
Product Designer (sole designer)
Team
Designer · PM · Frontend developer
Tools
HTML prototypes, Next.js, Supabase, Claude Code
Timeline
Oct 2026 — ongoing

Project overview

Water helps poker players record hands, take notes on opponents, follow tournament series, track their bankroll and ask an AI coach about a spot. Players often open it mid-game: one hand on the phone, the room dim, a decision coming.

The old interface gave every feature the same dark card at the same size, and the homepage looked the same whether you were at a table or planning a trip. I led the redesign from proposal to developer handoff.

01

Problem & goals

Main actions get lost

Recording a hand and taking table notes are the most frequent tasks, but they were the same size as everything else and moved around.

Every page looks alike

Home, events and hands were all lists of dark cards. You had to read the title to know where you were.

The AI coach is hidden

The feature that sets the app apart lived in a single input in the header, with no clear entry on the homepage.

The goals

One tap. One glance. One question away.

Frequent actions in one tap, in thumb reach · every page recognisable at a glance · the AI coach visible and used.

02

Six rounds on the homepage

The homepage carries the most weight, so I explored it widely before narrowing — from four dark-mode directions to a behaviour-led layout, then a deliberate range of styles.

Rounds 01–02 · Directions

Seven directions, each pairing a layout strategy with a palette — from a results dashboard to an opponent carousel and a bento grid.

Round 03 · Behaviour first

I stepped back from style and mapped the contexts — at the table, off the table, brand new — into placement rules, then critiqued rounds 01–02 against them. This became the recommended direction.

Rounds 04–06 · Fidelity and style

High-fidelity variants, then nine styles across three screens each (home, tournament list, tournament detail), and a deep dive on the one we chose.

03

Hero + Sheet: one layout language

Every page is built from the same three layers, so people always know where to look:

Hero — what this page is

A full-bleed colour block with one giant word, at most 45% of the first screen. Each area keeps its own colour: blue for home and AI, green for events, coral for hands.

Sheet — the content

Lists and tools on a sheet that overlaps the hero and can be dragged up. Order: main action, then personal info, then lists.

Dock — the main action

Primary actions and navigation stay in the thumb zone. One lime primary button per page at most.

04

From Figma to AI: designing in the prototype

For Water I moved my design process out of Figma. Instead of drawing frames and handing them over, I design directly in HTML prototypes, working with an AI coding assistant (Claude Code): I describe the change, review the result on my phone, and refine it until it's right.

Deliver easily

A prototype is a link, not a file to export. The PM and developer open the same version; the developer reads real layout, spacing and states instead of measuring a mockup.

Iterate quickly

A note from a review becomes a sentence, not a redrawn set of frames. Changes land in the prototype the same day, each with a changelog line.

Try out easily

Everyone tests the real flow on their own phone — real taps, sheets, empty states and errors — so feedback is about using it, not imagining it.

The design decisions stay mine: I set the direction, the Hero + Sheet rules and the design system, and review every change. AI takes on the production. So far that's 50 prototype files and one clickable prototype of the whole app with a real navigation stack, sheets and micro-interactions — record a hand from setup to result, browse a tournament schedule, seat opponents at a table, settle a stake group, chat with the AI coach. It's now on its third version.

05

Specs engineers can build from

For each function I wrote a spec: every screen and state captured straight from the prototype, the rules (with worked examples for anything that calculates money), open PM questions with a design default, engineering notes and analytics events.

Screenshots are produced by driving the prototype in a headless browser, so the spec and the prototype never drift apart.

06

The Design Hub

Halfway through, the process itself became the bottleneck: prototypes lived on my laptop, PM questions were scattered, decisions weren't written down, and the developer had no single place to see what was ready. So I designed and built a small internal site to fix it — Next.js on Vercel, Supabase for data and sign-in.

  1. (1)PrototypeNew version registered, with a changelog line for every change
  2. (2)PM questionOpen → discussing → decided
  3. (3)DecisionOne click from an answer, noting what must change
  4. (4)Dev taskPinned to a prototype version; flagged when a newer one exists
  5. (5)ShippedMoved across the board, linked to the commit

Rules, not reminders

A function can't move to "ready to dev" while it still has open questions — the database refuses and lists them.

Roles

Designer and PM edit everything; the developer moves tasks, adds commit links and answers questions.

Private by default

Prototypes are served only to signed-in teammates.

07

Beyond the phone

Water is built for the phone, so the desktop web version is for the work people do after a session — reviewing hands, settling money, tidying notes on players. The same Hero + Sheet language moves into a sidebar layout, and every page nudges people back to the phone for recording at the table.

Login & sign-up

One entry for both: Google in one tap, or an email with a six-digit code. People who sign up on the web are invited to add Water to their home screen.

Splash & loading

Six splash variants and three loading animations, built around the water-drop mark.

Poker tools

Calculators for win rate and ICM, with the answer shown in the hero.

08

Where it stands

The redesign is in development. The Hero + Sheet language now runs through the prototype's homepage, events, hands, table notes, bankroll and stake groups, and on to login, the desktop web version and the landing page. Every PM decision and dev task lives in the Design Hub instead of a chat thread.
